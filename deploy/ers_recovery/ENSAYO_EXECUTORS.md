# LOCAL fixture executors, not an OS installer

Delta over 15a27c24. `ensayo_fixture_executor.py` adds an exclusive mapped-fixture installer, external append/fsync inventory, external supervisor with an absolute monotonic deadline, pidfd-based termination of its original child processes, bounded independent local /proc collector and exact cleanup. The six v2 lifecycle regressions include both live holders omitted via [], only one supplied after capture, duplicate/substitute/mismatched child, pending spawn, partial reaped spawn and never-spawned cleanup. No canonical HOST /etc,/opt,/run installation, account/group changes, systemd calls or PM2 exists. The original 17 worker source pins are unchanged: this orchestrator stays outside the holder source directory and does not widen LOCAL guards.

The target must be absent and a direct `/tmp/ers-ensayo-fixture-*`. The control root must already be private0700 and a separate direct `/tmp/ers-ensayo-control-*`. The control ledger lives outside both holders. Before any target object creation it fsyncs an intent; after exclusive creation it fsyncs parent and exact identity/hash evidence. A pending/partial record holds, with no autonomous retry, overwrite or repair. Installer checks all source hashes before first target mutation. Files use O_EXCL/no-follow, directory handles and fixed relative paths. Fake unit files remain text in the local fixture `units` folder.

The supervisor is external to both original holder processes. It records itself and the deadline before spawning; each spawn intent precedes creation and PID/start/boot plus pidfd capture. It never restarts or adopts a receipt PID. It waits for socket and receipts under one absolute deadline, collects independently, records runtime objects, then terminates/reaps the exact original children using pidfd. Any holder failure or timeout stops the run; cleanup is a separate explicit call. If the supervisor itself dies, it cannot guarantee cleanup: an ambiguous spawn or ledger/removal state must hold for independent reconciliation. This is not a kernel timer or OS crash supervisor proof.

The collector accepts only the supervisor's owned Popen children with captured original identities. It bounds status/cgroup/fd enumeration/fdinfo, checks UID/GID/groups, executable dev/inode, actual cgroup, original held lock descriptor and FLOCK status against the receipts. It rechecks process identities. It compares rendered unit text hash but explicitly returns manager NOT_PRESENT_LOCAL_FIXTURE_NO_SYSTEMD. No loaded-unit or kernel attestation is manufactured. It never reads environment, logs, DB or bot paths.

Runtime inventory records an observation inside the exclusively created mapped fixture, not proof that only a particular syscall created it. Same-UID fixtures have no adversarial-user isolation. Cleanup reconciles the durable SPAWN_INTENT/SPAWNED/DEAD lifecycle against the supervisor's complete retained original-child registry. No attempted spawn allows an empty caller list to omit holders. Any spawn requires both exact roles, no pending intent, two distinct original PID/start/boot identities, matching DEAD evidence and the exact two retained OriginalChild objects with independent reaped/ENOENT checks. Partial launches, duplicates, substitutes and mismatched identities hold before first REMOVE_INTENT. A never-spawned installation alone may use an empty list. Cleanup then demands no uncertain creation records, a bounded exact tree census and full object identity/hash equality. Unknown entries, partial records, replaced parents, modified hashes or live originals hold before deleting. Each removal has durable intent/receipt and immediate identity recheck, using held directory FDs, without recursive or prefix deletion. Crash partway through cleanup preserves the ledger; no automatic continuation is implemented or claimed. Parent paths and ledger remain for review. The OS/root counterpart and root custodian remain unimplemented and unauthorized.
