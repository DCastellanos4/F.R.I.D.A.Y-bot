- Set DAVIS_ASYNC_PIPELINE=1, DAVIS_QUEUE=redis and DAVIS_ERS_PIPELINE_DB to the existing jarvis.db ONLY in jarvis-whatsapp. API keeps the existing synchronous behavior. Container additionally never queues channel api even if the flag is accidentally set.
- Keep DAVIS_PERSISTENCE=sqlite and all existing ledger/memory/history locations. Same-host WAL, not a second business database. Existing legacy outbox/responses were empty in preflight; stop producers and inspect again before migration. Do not adopt/replay legacy or uncertain entries.
- Pipeline is constructed but not started before authenticated WhatsApp connection open. Register live runtime factory and final adapter, then start consumption. Reconnect replaces both without a second worker pool.
- Intake copies only a bounded history snapshot and fixed allowlist: chatId bound to inbound.userId, urgencyDirective string and respuestaVoz boolean. No ctx functions, arbitrary options, API keys or OTP values are serialized. The original payload/message remains SQLite-only. Broker remains ID-only.
- The worker gets a freshly rebuilt runtime factory from the current socket and trusted dependencies, including OTP delivery to that job's inbound recipient. Internal lease/checkpoint/audit hooks from worker take precedence over runtime options. No stale closure from an earlier message is serialized or resurrected.
- ACK is sent as plain text and is not synthesized or stored as the answer in chat history. Existing auxiliary/deterministic WhatsApp paths remain outside the agent queue.
- Final delivery normalizes the final answer, sends voice if requested (synthesis failure can fall back before sending), then records the actual exchange and schedules normal condensation. An ambiguous voice send never falls back to a second text send. History bookkeeping failures never turn a resolved send into an automatic retry. Delivery uncertainty stays in SQLite, no resend.
- History snapshot is intake-time, not a guarantee that concurrent later queued messages see earlier answers that have not yet been delivered. No distributed per-chat ordering guarantee beyond the current single worker and existing history implementation.
- Runtime process death follows the reviewed durable intent/uncertain policy. No exactly-once external effects or maximum RTO is promised; isolated real recovery observed 60-90s.

Backup: preflight online SQLite backup passed integrity_check and foreign_key_check, mode0600. A fresh stopped-window copy is required before migration/flag. Retain both, no automatic deletion. Rollback must first stop intake/worker, count all pending/en_curso/uncertain rows, preserve them and disable the flag without routing those jobs into the legacy worker. Never copy an older business DB over newer state by default. Keep the additive schema and safe code if needed for reconciliation.
